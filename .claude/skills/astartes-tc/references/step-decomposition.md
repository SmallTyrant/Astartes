# Step 분해 규칙

**원칙**: 1 step = 1 사용자 동작 (버튼 탭, 옵션 선택, 입력, 드래그 등). 한 step에 여러 동작을 묶지 않는다.

이 규칙은 시트 컬럼이 `1 Step ~ 5 Step` 으로 분리되어 있는 이유와 직결된다. QA가 실행 중 어디서 멈췄는지를 정확히 마킹하려면 각 step이 단일 검증 가능한 동작이어야 한다.

---

## 어휘 (사용 가능한 동사)

| 동사       | 의미                       | 예시                                   |
| ---------- | -------------------------- | -------------------------------------- |
| 탭한다     | 단일 터치                  | "'+' 버튼을 탭한다"                    |
| 길게 누른다 | long press                 | "노트 썸네일을 길게 누른다"            |
| 드래그한다 | 끌기                       | "썸네일을 폴더 위로 드래그한다"        |
| 입력한다   | 텍스트 입력                | "이름 입력 필드에 'Q2'를 입력한다"     |
| 선택한다   | 리스트/메뉴에서 항목 선택  | "정렬 옵션 중 '최신순'을 선택한다"     |
| 스크롤한다 | 화면 스크롤                | "라이브러리 화면을 아래로 스크롤한다"  |
| 스와이프한다 | 좌/우/상/하 스와이프       | "노트를 왼쪽으로 스와이프한다"         |
| 확인한다   | (지양) — 대신 expected에 명시 | 사용 금지. "표시되어야 한다"로 |

**금지 동사**: "확인한다", "본다", "체크한다" — 모호. 검증은 `expected`에 결과 표현으로 적는다.

---

## Before / After 예시

### 예시 1: 폴더 생성

```
나쁨 (1 step에 4개 동작 압축):
  steps: ["라이브러리 '+' 버튼에서 '폴더'를 선택해 'Q2'를 생성한다"]

좋음 (4 step):
  steps: [
    "'+' 버튼을 탭한다",
    "'폴더' 옵션을 탭한다",
    "이름 입력 필드에 'Q2'를 입력한다",
    "'생성' 버튼을 탭한다"
  ]
```

### 예시 2: 플랜 업그레이드 (Face ID)

```
나쁨:
  steps: ["프로 플랜 카드를 탭하고 Face ID로 결제한다"]

좋음:
  steps: [
    "설정 → 구독 화면에 진입한다",
    "'프로' 플랜 카드를 탭한다",
    "결제 시트에서 '구매' 버튼을 탭한다",
    "Face ID 인증을 완료한다"
  ]
```

### 예시 3: 노트 PDF 가져오기

```
나쁨:
  steps: [
    "라이브러리에서 가져오기를 탭하고 PDF를 선택한다",
    "PDF가 노트로 저장되는지 확인한다"
  ]

좋음:
  steps: [
    "라이브러리 화면에서 '+' 버튼을 탭한다",
    "'가져오기' 옵션을 탭한다",
    "파일 피커에서 'sample.pdf'를 선택한다",
    "'열기' 버튼을 탭한다"
  ]
  expected: "PDF가 라이브러리 최상단에 새 노트로 추가되어야 한다"
```

확인 동작은 step에서 빼고 `expected`에 옮긴다.

## 5 step 한도 처리법

시트의 `1 Step ~ 5 Step` 컬럼은 **절대 한도**다. 동작이 6개 이상이면 다음 중 하나로 처리:

### A. 사전조건으로 압축

준비 단계는 `precondition`으로 옮긴다.

```
나쁨 (7 step):
  steps: [
    "앱을 실행한다",
    "로그인한다",
    "라이브러리 화면에 진입한다",
    "'+' 버튼을 탭한다",
    "'폴더' 옵션을 탭한다",
    "이름을 입력한다",
    "'생성' 버튼을 탭한다"
  ]

좋음 (4 step):
  precondition: "앱 로그인 완료, 라이브러리 화면 진입 상태"
  steps: [
    "'+' 버튼을 탭한다",
    "'폴더' 옵션을 탭한다",
    "이름 입력 필드에 'Q2'를 입력한다",
    "'생성' 버튼을 탭한다"
  ]
```

### B. 시나리오 둘로 쪼개기

진짜로 6개 이상의 검증 step이 필요한 경우, TC를 둘로 분리하고 두 번째 TC의 `precondition`에 첫 번째의 종착 상태를 명시.

```
TC #5 — 폴더 생성
  steps: [...4개...]
  expected: "Q2 폴더가 라이브러리에 표시되어야 한다"

TC #6 — 폴더 안에 노트 생성
  precondition: "Q2 폴더가 생성된 상태 (TC #5 결과)"
  steps: [...4개...]
  expected: "노트가 Q2 폴더 안에 추가되어야 한다"
```

### C. 의미 단위 압축 (드물게)

같은 화면에서 연속된 자명한 동작 (예: 동일 폼의 여러 필드 입력)은 1 step으로 묶어도 된다. 단, **버튼 탭은 절대 압축 금지**.

```
허용:
  "이름·전화번호·이메일을 모두 입력한다"  (입력 필드 3개, 모두 같은 폼)

금지:
  "이름을 입력하고 '다음' 버튼을 탭한다"  (입력 + 버튼 = 다른 동작)
```

---

## 자주 만드는 실수

| 실수                                 | 고치는 방법                                   |
| ------------------------------------ | --------------------------------------------- |
| "탭하고 입력한다"                    | 두 step으로 분리                              |
| "확인한다" / "본다"                  | step에서 제거, `expected`에 결과로 표현       |
| 사전 준비를 step 1에 박음            | `precondition`으로 이동                       |
| 한 시나리오에 6+ 동작                | A/B/C 중 하나로 처리                          |
| step 안에 결과 서술 ("...면 ...된다") | step은 사용자 동작만, 결과는 `expected`로     |

---

## 체크리스트

TC 작성 후 자가 점검:

1. 각 step에 동사 1개씩만 있는가? ("탭한다 + 입력한다" 같은 묶음 없음)
2. step 개수가 1~5 범위인가?
3. "확인한다" 같은 모호 동사가 없는가?
4. 6개 이상이면 precondition 압축 또는 시나리오 분할을 했는가?
5. 결과 서술이 step이 아니라 `expected`에 있는가?

위반 시 JSON을 먼저 고치고 워크북을 재생성한다 (시트만 수정하면 다음 export에서 덮어써진다).
